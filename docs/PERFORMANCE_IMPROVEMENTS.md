# План улучшения производительности Hoshira

Этот файл отслеживает перенос применимых идей из:

- `hoshi-io/hoshi`, снимок `0252e456442295ad0e7f0d85fccfc8beeeb48ba0`;
- `Helandy/YummyTV`, снимок `ad9cd7867128bb860cfe15cabebe8be4485c6dfa`.

Сравнение выполнено 2026-08-29 с текущим локальным состоянием Hoshira, включая
незакоммиченные изменения.

## Правило завершения пунктов

Пункт можно перевести в состояние `[x]` только после выполнения его критериев готовности и
успешного запуска соответствующих unit-тестов. Запускаются только тестовые Gradle-задачи — без
`build`, `assemble`, упаковки установщиков и release-сборок.

Команды проверки:

```powershell
# Изменения общего или desktop-кода
.\gradlew.bat :desktopApp:test

# Изменения Android-кода
.\gradlew.bat :androidApp:testDebugUnitTest

# Изменения общего кода, затрагивающие обе платформы
.\gradlew.bat :desktopApp:test :androidApp:testDebugUnitTest
```

Допускается запуск более узкого набора через `--tests`, если после него также запущена полная
тестовая задача затронутого модуля. Если тесты не удалось запустить из-за окружения или они не
прошли, пункт остаётся незавершённым с пометкой `[!]` и описанием блокера в журнале.

Статусы:

- `[ ]` — не начато;
- `[-]` — в работе;
- `[!]` — заблокировано;
- `[x]` — завершено и тесты прошли.

## Главные улучшения

### P0 — убрать частые синхронные записи прогресса

- [x] Перенести сохранение `user-data.json` с UI-потока на отдельный фоновый I/O writer.
- [x] Объединять обновления прогресса и сохранять их не чаще одного раза в 10 секунд.
- [x] Немедленно сбрасывать ожидающий прогресс при паузе, перемотке, смене серии и закрытии
  плеера.
- [x] Не выполнять отдельную запись файла для громкости или качества, если их можно сохранить
  вместе с очередным снимком прогресса.
- [x] Добавить тесты на объединение обновлений и обязательный финальный flush.

Текущее состояние: Android сообщает прогресс раз в 1 секунду, Windows — раз в 750 мс; каждый
вызов синхронно сериализует и атомарно перезаписывает весь `user-data.json`.

Критерий готовности: во время непрерывного просмотра файл записывается не чаще одного раза в
10 секунд, UI-поток не выполняет файловый ввод-вывод, а при штатном выходе теряется не более
последних нескольких секунд прогресса.

Проверка: `:desktopApp:test` и `:androidApp:testDebugUnitTest`.

### P1 — ограничить память ExoPlayer

- [x] Ввести профили оперативного буфера для обычных и low-RAM устройств.
- [x] Для профиля по умолчанию использовать ориентир 10–30 секунд и лимит 24–32 МБ.
- [x] Для low-RAM использовать ориентир 5–15 секунд и лимит около 16 МБ.
- [x] Установить `setTargetBufferBytes(...)` и
  `setPrioritizeTimeOverSizeThresholds(false)`.
- [x] Проверить переключение серии, сохранение позиции после перемотки, восстановление позиции и
  пороги повторной буферизации unit-тестами; smoke декодера и Surface на реальном устройстве
  остаётся рекомендуемой ручной проверкой перед релизом.

Текущее состояние: Android-плеер запрашивает буфер 30–75 секунд, не задаёт явный лимит байтов и
приоритизирует время над ограничением размера.

Критерий готовности: профиль выбирается с учётом `ActivityManager.isLowRamDevice`, настройки
соответствуют инвариантам `DefaultLoadControl`, воспроизведение и восстановление позиции покрыты
тестами.

Проверка: `:androidApp:testDebugUnitTest`.

### P1 — добавить offline-first кэш API

  ошибке.
- [x] Добавить кэш деталей релиза с TTL 6–24 часа.
- [x] Добавить кэш сведений об источниках/сериях там, где URL не являются одноразовыми.
- [x] Объединять параллельные одинаковые запросы mutex-ом по ключу.
- [x] Выполнять обновление устаревшей главной в фоне без очистки уже показанных данных.
- [x] Добавить явную инвалидацию для пользовательского обновления и штатной очистки кэшей.

Критерий готовности: повторное открытие главной и деталей не требует сети в пределах TTL; при
ошибке сети доступен последний корректный снимок; два одновременных запроса одного ключа вызывают
одну сетевую загрузку.

Проверка: `:desktopApp:test` и `:androidApp:testDebugUnitTest`.

### P1 — использовать единый HTTP-клиент

таймауты остаются специфичными для каждого типа запросов; отмена coroutine отменяет сетевой вызов.

Проверка: `:desktopApp:test` и `:androidApp:testDebugUnitTest`.

### P1 hotfix — восстановить надёжную загрузку изображений на мобильной сети

- [x] Сохранить исходное качество `medium/big/mega/fullsize`: device-smoke показал, что tier ниже

## Уже реализовано — не переделывать без измерений

- Device-aware memory cache Coil: 15% для обычных и 10% для low-RAM Android-устройств.
- Раздельные thumbnail/standard/high/full URL изображений.
- Lazy-списки со стабильными ключами.
- Debounce поиска 260–280 мс.
- R8 и shrink resources для Android release.
- Decoder fallback в Android ExoPlayer.

## Не переносить буквально

- Полную Rust/Tauri-архитектуру Hoshi ради одной оптимизации.
- Полную модульную структуру YummyTV без продуктовой необходимости.
- Hoshi `LazyCardGrid`: он подгружает страницы по sentinel, но не превосходит Compose lazy-layout
  по виртуализации уже загруженных элементов.
- Текущий proxy handler Hoshi как образец настоящего streaming: несмотря на потоковый upstream,
  обработчик собирает сегмент в `Vec<u8>` перед передачей WebView.

Исходный код сравниваемых проектов нельзя переносить буквально без отдельной проверки лицензий:
Hoshi использует AGPL-3.0, YummyTV — CC BY-NC 4.0, Hoshira — проприетарную лицензию. В этом плане
фиксируются архитектурные идеи для самостоятельной реализации.
